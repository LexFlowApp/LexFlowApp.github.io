法律人用好 AI 的关键在于提供充分的信息

2026年10月9日　·　全文共 1689 字　·　阅读时间约 5 分钟

一、充分信息对 AI 的必要性

AI 其实是你刚录用的私人助理，具备足够专业知识的应届博士，却还不够了解你的工作风格、作业流程和交付标准。若只丢给他一句话，让他做个法律研究，产出的东西会很整齐，但没有用。

于是你给他做了员工培训，告诉他做法律研究要在判例、裁判观点和立法观点上做功夫，顺序是先判例、再最高院观点、最后立法者观点。但这个博士很健忘，今天在工位上说的，明天换个会话就忘了。

于是你写了一份员工手册，把要求都记在里面，并告诉他做事之前先看这份手册。终于，他每次都能按你的要求做事，成果也慢慢达到你的预期。

从网页对话转向 Agent，相当于给这个博士生配了工位和电脑，让他能真正干活；而编制和使用这份员工手册的过程，就是标准化、SOP、工作流，就是让 AI 取得充分信息的过程。

人类尚且需要信息充分、需求明确、标准清楚、流程稳定，才能把一件事持续做好，AI 更需要如此。

所以法律人用好 AI 的关键，在于向 AI 提供充分的信息。所谓充分的信息，无非是「完整的项目情况」和「工作流」两样。知道项目的全貌，又清楚这类工作的流程，再加上 AI 博士的脑力，事情不可能做不好。

二、既有 Agent 记忆机制的瑕疵

既有 Agent 通常借「记忆」机制来提供上述信息。各类记忆机制各不相同，但多存在同一个问题：难以管理。

其一，区分全局与项目层级的 Agent.md 等记忆文件，其内容通常是对工作要求的杂乱记录，且局限于某一个项目，并未提炼出一份可反复适用于同类工作的工作流。工作流程信息的供给是低效的。

其二，项目文档通常篇幅较长、数量较多，Agent.md 等记忆文件不适合用来存放项目情况；并且，AI 也无需在任何任务皆完整阅读全部项目文档。项目信息的供给因此不充分或有冗余。

其三，Agent.md 等记忆文件多以 Markdown 形式存在，AI 读它无需转换，但却不适合无技术背景的法律人阅读与编辑；项目文档则多以 Word、Excel、PDF 形式存在，人读着改着顺手，但 AI 要先转成 Markdown 才能读，输出时又要转回 Word。双方来回转换，交互成本颇高。

这三点共同导致记忆难以管理，让我们难以在每一个任务里，持续且低成本地向 AI 提供充分的信息。

三、向 AI 提供充分信息的方案

既有的解决方案是 Obsidian 加 Agent，即通过 Obsidian 建立知识库。Obsidian 是一个外接的 Markdown 编辑器，对 Markdown 文件能做出接近 Word 的编辑体验。所谓知识库，就是以 Markdown 形式保存工作流和项目文档的文件夹，与 Agent 链接之后，就能对工作流和项目文档做精确管理。靠 Obsidian 自行建立知识库体系，上述问题可以解决。

但 Obsidian 终究只是一个 Markdown 编辑器。它与 Agent 的结合不是与生俱来的，知识库体系也不是开箱即有的。得先掌握建立知识库的方法论，才能在它里面搭出一套与 Agent 链接的知识库。从两者的下载安装，到知识库内部层级的建立，每一步都是门槛，对没用过 Agent 的用户尤其不利。

基于此，我尝试提出一个方案：把知识库内嵌进 Agent。Agent 天然围绕知识库工作，展开工作之前，先在里面找有没有相关的工作流或项目背景；完成工作之后，总结经验、提炼成可复用的工作流，把成果和中间文件归档保存。这样，Agent 始终能掌握充分的信息，始终能交付高质量的成果。

依据这个方案，诞生了 LexFlow。

四、LexFlow

LexFlow 是一个 macOS 桌面应用，基于 DeepSeek Harness 开发。它通过「工作流」「档案室」「工作台」三个入口，分别承接工作方法、项目材料与工作成果的保存和编辑。

「工作流」，是存放、预览和调整工作流适用规则的地方。经过提炼的工作流可以存在这里，也可以在这里预览内容；也可以调整适用规则——可以让 LexFlow 在每次开始工作时固定读取某个工作流，可以在它遇到相关工作时再读取，也可以只在你明确指令它读取时才读取。LexFlow 遵循你写下的工作流，你不必反复说明自己是谁、有什么要求。

「工作流」界面里还分两种文件类型：一种是「工作流」，是已经成体系并明文化的工作流程；另一种是「长期记忆」，是那些还没成体系、零散的经验和规范。不必等到思考成熟才记录，随时都可以向 LexFlow 发号施令。

「档案室」，是存放和预览项目材料的地方。Word、Excel、PDF 等文件导入之后，原件留在档案室里，同时把其中的文字提取成 Markdown 一并存放，既能建立完整的项目信息，也免去对同一份文件反复提取的麻烦。

「工作台」，是直接编辑上述 Markdown 文件的地方。在这里可以把通常编辑 Markdown 时那种「写代码式」的体验，换成「Word」般的交互体验，轻松上手，顺畅编辑。

三者都在你自己指定的知识库里——也就是电脑上的一个文件夹，形式也就是普通的 Markdown 文本，随时能打开、能手动改，也能整个搬到别处去。知识库完全存在本地，LexFlow 不设服务器，不上传任何东西。

通过这三个入口，方法被清晰管理，成果被持久保存；并且随着长期使用，新的工作流不断积聚，形成 AI 的长期复利。
